### 4.1 §3.1 程序性记忆 — ⚠️ 补触发条件

### 4.2 §3.2 `infer = false` — ✅ 准确，补三条

`main.py` L880-914：逐条 embed + `_create_memory` 原样入库 ✅。补充：跳过 `role=="system"`（L891）；`name` → `actor_id`（L897-899）；无 LLM、无 hash 去重、无实体链接。

### 4.3 §3.3 / §3.3.1 — ❌「tool 过程只当上下文」是错的

`mem0/memory/utils.py` 的 `parse_messages`：

```python
# Skip messages without textual content (e.g. assistant tool-call
# messages that carry `tool_calls` but no `content` key).
if content is None:
    continue
if role == "system":      response += f"system: {content}\n"
elif role == "user":      response += f"user: {content}\n"
elif role == "assistant": response += f"assistant: {content}\n"
```

- `content is None`（assistant 带 `tool_calls`）→ **丢弃**
- `role == "tool"`（工具结果）→ **无分支，完全不进**
- 只有 system / user / assistant 的**文本 content** 进抽取

**结论：tool 调用与 tool 结果不参与抽取。** 这一条常被解读文章写反。

## 5. §4 检索（Retrieval）

### 5.1 §4.0 / §4.1 — ✅ 补一条硬约束

`search()` 的 `filters` **必须至少含 `user_id` / `agent_id` / `run_id` 之一**，否则 `ValueError`；且 `search()` / `get_all()` **不接受顶层** `user_id`（`main.py` L800-802、L1379）。

### 5.2 §4.2 管线 — 逐点核对

| 点 | 原文 | 判定 | 证据 / 应改成 |
|---|---|---|---|
| 1 | embed query，用建库同款 embedding；默认闭源 | ✅ | L1645；`embeddings/configs.py` 默认 `openai` |
| 2 | 主库 ANN | ✅ | 默认 `qdrant` |
| 3 | `max(topK×4, 60)` | ✅ | L1648 |
| 4 | BM25 → 0~1 | ✅ 可补 | L1654；`scoring.py` L16-53 sigmoid 参数表 |
| 5 | 实体加分 0~0.5，越少越高 | ✅ 可补公式 | `_compute_entity_boosts` L1733+ |
| 6 | **三路相加除以 2.5** | ❌ | 除数**自适应** 1.0 / 1.5 / 2.0 / 2.5（`scoring.py` L78-84） |
| 7 | threshold = 最低分数 | ❌ | threshold **只卡语义分，且在融合之前**（`scoring.py` L111） |

**第 6 点正确写法**（`scoring.py` L78-84）：

```python
max_possible = 1.0
if has_bm25:   max_possible += 1.0      # 语义 + BM25 = 2.0
if has_entity: max_possible += 0.5      # 三路全开 = 2.5；只有实体 = 1.5
combined = min(raw_combined / max_possible, 1.0)
```

**什么时候不是 2.5？** ① 向量库未实现 `keyword_search`（`main.py` L543-550 告警并禁用 hybrid，官方点名 qdrant / elasticsearch / pgvector）；② query 没抽出实体。

**第 7 点正确写法**：`if semantic_score < threshold: continue`（默认 0.1）——语义分不够，BM25 与实体加分再高也直接丢。

**补充 A：BM25 在 Qdrant 里是原生 sparse 向量**（`qdrant.py` L454-484）：`using="bm25"` 命名向量槽，输入取 `payload["text_lemmatized"]`（L513）。`_has_bm25_slot` 为假 → 返回 `None` → hybrid 关闭。

**补充 B：实体加分完整公式**（`main.py` L1733+）：

```python
num_linked = max(len(linked_memory_ids), 1)
memory_count_weight = 1.0 / (1.0 + 0.001 * ((num_linked - 1) ** 2))
boost = similarity * 0.5 * memory_count_weight        # similarity < 0.5 跳过
memory_boosts[id] = max(已有, boost)                  # 同一条记忆取所有实体的最大值
```

参数：query 实体去重后**最多 8 个**；实体库 `top_k=500`；`ThreadPoolExecutor(max_workers=4)`；filters 只带 `user_id/agent_id/run_id`。

稀有度实测：

| 该实体挂了几条记忆 | `memory_count_weight` | boost 上限（similarity=1） |
|---|---|---|
| 1 | 1.000 | 0.500 |
| 2 | 0.999 | 0.4995 |
| 10 | 0.925 | 0.462 |
| 50 | 0.294 | 0.147 |
| 100 | 0.093 | 0.046 |
| 1000 | 0.001 | 0.0005 |

**补充 C**：`search(explain=True)` 返回 `score_details`（`semantic_score` / `bm25_score` / `entity_boost` / `max_possible_score` / `final_score`）。

### 5.3 §4.3 — 📌 整段缺失：mem0 里「rerank」是两个不同的东西

| | 内部三路融合 | 外部 reranker |
|---|---|---|
| 触发 | 默认 | `search(..., rerank=True)` + 配置 `reranker` |
| 实现 | `score_and_rank` | `self.reranker.rerank(query, original_memories, limit)`（`main.py` L1379 内） |
| 模型 | 无 | Cohere `rerank-v3.5` / Zero Entropy `zerank-1` / `cross-encoder/ms-marco-MiniLM-L-6-v2` / `BAAI/bge-reranker-base` / LLM reranker（默认 `gpt-5-mini`） |
| 失败 | — | 打 warning，**退回原向量排序结果** |

纯 CPU 只能用 `sentence_transformer` / `huggingface` 两个本地 cross-encoder。

**✅「Mem0 默认不做 query rewriting」**：`search()` 里没有任何改写步骤，属实。

## 6. §5 本地模型

前四小节是作者经验，无源码可核，不改。

**📌 必补**：`spaCy en_core_web_sm` 是**实体抽取与词形还原的共同依赖**（`spacy_models.py` 同时提供 `get_nlp_full()` 与 `get_nlp_lemma()`）。缺失时：

- 实体抽取 → `[]` → 实体加分消失，`max_possible` 变 1.0 或 2.0
- `lemmatize_for_bm25` → **原样返回原文**（`lemmatization.py` fallback）→ BM25 匹配质量下降

装法：`pip install mem0ai[nlp]`，或 `python -m spacy download en_core_web_sm`。

**可补**：官方支持的本地 provider —— LLM：`ollama` / `vllm` / `lmstudio` / `deepseek`；embedding：`ollama` / `huggingface` / `fastembed` / `lmstudio`。
